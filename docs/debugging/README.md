# Debugging

Notes from revival attempts on real robots, kept so the next person does not have to re-derive them.

- [`live-hardware-debug.md`](live-hardware-debug.md) — a log of an actual revival attempt: confirmed
  MAC addresses, Wi-Fi-only versus pairing QR codes, the "Moxie Direct" access point, and the wall a
  pre-801 robot hits. It reads the endpoint (`om`) QR but never connects, because older firmware is
  pinned to Google Cloud IoT Core with hostname-checked TLS. This is why the 801/803 firmware gate
  matters.
- [`qr-command-findings.md`](qr-command-findings.md) — the historical log from the
  [`tools/qr-rig`](../../tools/qr-rig/README.md) camera rig, which showed candidate QR codes to a robot and
  timed its scan beeps to see which ones it acted on. That search is closed: decompiling the scanner
  proved the QR grammar has exactly four debug commands and no hidden ones
  ([QR commands](../reverse-engineering/protocol/qr-commands.md)). The file is regenerated by
  `tools/qr-rig/overnight.py`.

For pre-801 robots the fix is a reflash to 803, not a QR code; see
[revive your Moxie](../guides/revive-your-moxie.md).
